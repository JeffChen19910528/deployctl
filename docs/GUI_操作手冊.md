## 1. 系統簡介

deployctl 桌面版是一套以 Avalonia UI 建構的圖形化部署管理工具，提供應用程式版本管理、多環境部署、備份與稽核等完整功能，適合不熟悉命令列操作的使用者透過視覺化介面管理部署流程。

| 功能模組 | 說明 |
|---|---|
| 應用程式管理 | 建立與維護應用程式、環境及部署目標 |
| 版本管理 | 打包與管理應用程式發行版本 |
| 部署管理 | 執行差異比較、模擬部署、正式部署及版本回滾 |
| 備份管理 | 自動備份、保護重要備份及清理過期備份 |
| 歷史紀錄 | 查看部署歷史與完整稽核記錄 |
| 異常復原 | 偵測並修復卡在進行中狀態的部署作業 |

## 2. 啟動應用程式

雙擊執行 **deployctl-desktop.exe** 即可啟動桌面版。

**首次啟動流程：**
- 程式啟動後會自動初始化本機資料庫（SQLite），無需額外安裝資料庫。
- 主視窗開啟後，左側顯示導覽列，右側為各功能的內容區域。
- 所有資料預設儲存於 `%APPDATA%\deployctl\` 目錄下。

> **提示：** `deployctl-desktop.exe` 與 `deployctl.exe`（命令列版）共用同一份資料，兩者可並行使用。

## 3. 主視窗說明

主視窗分為兩個區域：**左側導覽列**（寬度 200px）與**右側內容區域**。

```
┌──────────────────┬────────────────────────────────────────┐
│  deployctl       │                                        │
│                  │         （內容區域）                    │
│  ▸ 應用程式      │                                        │
│  ▸ 版本          │   依所選功能顯示操作介面               │
│  ▸ 部署          │   （資料表格、篩選條件、操作按鈕等）   │
│  ▸ 備份          │                                        │
│  ▸ 歷史          │                                        │
│  ▸ 復原          │                                        │
└──────────────────┴────────────────────────────────────────┘
```

| 區域 | 說明 |
|---|---|
| 左側導覽列 | 顯示系統標題與功能模組清單，點擊項目切換右側內容 |
| 右側內容區域 | 依所選功能顯示對應操作介面，包含資料表格、操作按鈕等 |

> **提示：** 視窗預設大小為 1100 × 720，可自由調整；工具列在視窗較窄時會自動換行。

## 4. 快速開始：首次設定與上版 SOP

這一節說明從零開始到完成第一次部署的完整操作流程。若你已完成首次設定，每次上版只需重複 [4.3 每次上版流程](#43-每次上版流程) 的步驟即可。

---

### 4.1 首次設定（只需一次）

首次使用前，需先在系統中登記你要管理的應用程式、環境與部署目標。以下三個步驟依序完成即可，之後不需要重複做。

**步驟 1：建立應用程式**

1. 點擊左側導覽列 **應用程式**。
2. 點擊工具列 **建立應用程式**。
3. 輸入應用程式名稱（例如 `MyApp`），選填說明後按 **確定**。

**步驟 2：新增環境**

1. 點擊工具列 **新增環境**。
2. 在彈出視窗中選擇剛建立的應用程式。
3. 輸入環境名稱（例如 `production`），按 **確定**。

> 環境代表部署的階段，例如 `production`（正式）、`staging`（測試）。同一個應用程式可以有多個環境。

**步驟 3：新增部署目標**

1. 點擊工具列 **新增目標**。
2. 選擇應用程式與環境。
3. 填入目標名稱（例如 `web1`）、作業系統類型（Windows / Linux）、主機名稱（本機填 `localhost`）。
4. 在「部署路徑」欄位輸入，或按 **瀏覽…** 選擇目標機器上程式實際存放的資料夾（例如 `C:\IIS\MyApp`）。
5. 確認備份排除目錄設定（預設 `log;logs`，以分號分隔），按 **確定**。

> 完成後，應用程式頁面清單中會出現剛建立的應用程式、環境與目標。

---

### 4.2 來源資料夾結構說明

建立版本前，需先在本機準備好一個**來源資料夾**，其結構必須與目標機器上部署路徑的目錄結構一致。

**範例：** 若部署路徑為 `C:\IIS\MyApp`，則來源資料夾的內容應對應如下：

```
來源資料夾（例如 C:\Build\patch\）    →    C:\IIS\MyApp\（部署後）
├── bin\                                   ├── bin\
│   └── MyApp.dll    ← 覆蓋              │   └── MyApp.dll    ← 已更新
└── appsettings.json ← 覆蓋              ├── appsettings.json ← 已更新
                                           ├── MyApp.exe        ← 未異動（保留）
                                           └── web.config       ← 未異動（保留）
```

**重要規則：**

- 來源資料夾只需放**這次要新增或更新的檔案**，不需要提供完整的應用程式目錄。  
  部署行為：來源有的檔案會**新增或覆蓋**到目標路徑；目標上原有但來源沒有的檔案**不會被刪除**，原封不動保留。
- 每次有更新請建立新版本號（例如從 `1.0.0` 改為 `1.0.1`）。版本一旦建立即不可修改。
- 不需要打包成 zip，直接選擇資料夾即可，系統會自動壓縮並計算 SHA-256。

---

### 4.3 每次上版流程

首次設定完成後，每次要更新版本時依下列步驟操作：

**步驟 1：準備來源資料夾**

將這次要新增或更新的檔案整理到一個資料夾，維持與目標路徑一致的子目錄結構（見 [4.2](#42-來源資料夾結構說明)）。不需要放完整的應用程式，只放本次有異動的檔案即可。

**步驟 2：建立版本**

1. 點擊左側導覽列 **版本**。
2. 選擇應用程式後點擊 **建立版本**。
3. 填入版本號（例如 `1.0.1`）、選擇來源資料夾，按 **確定**。

**步驟 3：確認差異（建議）**

1. 點擊左側導覽列 **部署與回滾**。
2. 依序選擇應用程式／環境／目標／剛建立的版本。
3. 點擊 **查看差異**，確認清單中只有預期的新增（`+`）與修改（`~`）項目，沒有意外的內容。

**步驟 4：模擬部署（建議）**

點擊 **部署（模擬執行）**，跑一次完整流程但不修改任何實際檔案，確認流程無誤。

**步驟 5：正式部署**

點擊 **部署（正式執行）** → 確認對話框顯示備份提示 → 按 **是**。  
系統會依序：備份目前目標目錄 → 將來源資料夾的檔案複製覆蓋到目標路徑 → 驗證 SHA-256 → 寫入稽核紀錄。

**步驟 6：確認結果**

點擊左側導覽列 **歷史與稽核紀錄** → 切換至**部署歷史**分頁，確認最新一筆記錄狀態為 `Completed`。

> **部署後發現問題？** 至**部署與回滾**頁面，在版本下拉選單中選擇要退回的舊版本，按**回滾到先前的版本**即可還原。回滾前系統會自動備份目前狀態。

## 5. 應用程式管理

點擊左側導覽列中的 **應用程式** 進入此頁面。本頁面管理所有應用程式、環境（Environment）及部署目標（Target）的設定。

**頁面工具列按鈕：**

| 按鈕 | 功能 |
|---|---|
| 建立應用程式 | 新增一個應用程式條目 |
| 新增環境 | 在已有的應用程式下新增環境（如 Production、Staging） |
| 新增目標 | 在已有的環境下新增部署目標 |
| 修改部署目標 | 修改已建立的部署目標設定（名稱、路徑、主機、OS、備份排除） |
| 編輯排除清單 | 僅調整指定目標的備份排除目錄 |
| 重新整理 | 重新從資料庫載入最新資料 |

**應用程式清單欄位：**

| 欄位 | 說明 |
|---|---|
| Application | 應用程式名稱 |
| Environments | 該應用程式下的所有環境名稱 |
| Targets | 各環境下的部署目標摘要（環境名稱與目標名稱） |

### 5.1 建立應用程式

1. 點擊工具列 **建立應用程式** 按鈕。
2. 在彈出視窗中輸入應用程式名稱（必填）。
3. 選擇性填寫說明文字。
4. 點擊 **確定** 完成建立。

> 同名應用程式無法重複建立，系統會提示錯誤。

### 5.2 新增環境

1. 點擊工具列 **新增環境** 按鈕。
2. 在彈出視窗中選擇所屬應用程式。
3. 輸入環境名稱（如 Production、Staging、UAT）。
4. 視需要勾選「需要審核」選項。
5. 點擊 **確定** 完成建立。

### 5.3 新增部署目標

1. 點擊工具列 **新增目標** 按鈕。
2. 選擇所屬應用程式及環境。
3. 輸入目標名稱、作業系統類型（Windows / Linux）。
4. 輸入主機名稱（預設為 `localhost`）。
5. 輸入或透過 **瀏覽…** 按鈕選擇部署路徑。
6. 設定備份排除目錄（預設為 `log;logs`，多個目錄以分號分隔）。
7. 點擊 **確定** 完成建立。

> **提示：** 部署路徑為目標機器上應用程式實際部署的資料夾路徑。

### 5.4 修改部署目標

用於修改已建立的部署目標的所有設定，包含目標名稱、作業系統、主機位址、部署路徑及備份排除目錄。

1. 點擊工具列 **修改部署目標** 按鈕。
2. 在彈出對話框的選擇器中依序選擇 **應用程式 → 環境 → 目標**。
3. 選定目標後，下方欄位會自動帶入該目標的現有設定值。
4. 修改需要變更的欄位：
   - **目標名稱**：目標的識別名稱
   - **作業系統**：Windows / Linux
   - **主機名稱**：主機位址（本機填 `localhost`）
   - **部署路徑**：可直接輸入或按 **瀏覽…** 選擇資料夾
   - **備份排除目錄**：備份時略過的子目錄，以分號分隔
5. 點擊 **確定** 儲存變更。

> **注意：** 修改部署路徑後，下次執行差異比較或部署時會以新路徑為準，請確認新路徑存在且有正確的存取權限。

### 5.5 編輯備份排除清單

若只需要快速調整備份排除目錄，可使用此捷徑，不需要開啟完整的修改目標對話框。

1. 點擊工具列 **編輯排除清單** 按鈕。
2. 從對話框中選擇要編輯的部署目標。
3. 修改排除目錄清單（多個目錄以分號分隔，例如：`log;logs;temp`）。
4. 點擊 **確定** 儲存設定。

> 排除清單中的目錄在備份時會被略過，可避免備份大量的日誌檔案。

## 6. 版本管理

點擊左側導覽列中的 **版本** 進入此頁面。本頁面管理各應用程式的發行版本，每個版本對應一個壓縮部署包。

**版本清單欄位：**

| 欄位 | 說明 |
|---|---|
| Release ID | 系統自動產生的唯一識別碼 |
| Version | 版本號碼（如 1.0.0、2024.11.01） |
| Created | 建立時間 |
| By | 建立者（目前登入的 Windows 使用者名稱） |

### 6.1 建立新版本

1. 在頁面頂部的應用程式下拉清單中選擇目標應用程式。
2. 點擊 **建立版本** 按鈕。
3. 在彈出對話框中填入：
   - 版本號碼（必填）
   - 來源資料夾路徑（即要打包的應用程式目錄，必填；來源資料夾結構說明請參考 [4.2](#42-來源資料夾結構說明)）
   - 版本備註（選填）
4. 點擊 **確定**，系統將自動壓縮來源資料夾並計算 SHA-256 校驗碼。
5. 完成後版本會出現在清單中。

> **建議：** 版本號碼使用語義化版本格式（如 `1.2.3`）或日期格式（如 `2024.11.01`）。版本一旦建立即不可修改，有更新請建立新版本號。

### 6.2 查看版本詳情

在版本清單中，**雙擊**任一版本列即可開啟詳情視窗，顯示：
- 版本 ID 與版本號
- 包含的檔案清單與 SHA-256 校驗碼
- 版本備註

## 7. 部署管理

點擊左側導覽列中的 **部署** 進入此頁面。提供差異比較、模擬部署、正式部署與版本回滾四項操作。

**目標選擇器（頁面上方）：** 依序選擇 **應用程式 → 環境 → 目標 → 版本**，四個下拉選單會依序連動更新，所有操作都以目前選擇器中的設定為準。

**操作按鈕：**

| 按鈕 | 說明 |
|---|---|
| 差異比較 | 比較版本差異，不做任何實際異動 |
| 模擬部署 | 執行完整部署流程但不修改任何檔案 |
| **部署**（藍色） | 正式部署到目標 |
| 回滾 | 將目標還原至指定的歷史版本 |

### 7.1 差異比較

比較所選版本與目標目前部署版本之間的檔案差異，**不做任何實際異動**。

1. 選擇應用程式、環境、目標及要比較的版本。
2. 點擊 **差異比較** 按鈕。
3. 下方結果區域顯示差異內容：
   - `+` 代表新增檔案
   - `~` 代表修改檔案
   - `-` 代表刪除檔案
4. 同時顯示新增、修改、刪除及不變的檔案數量統計。

### 7.2 模擬部署（Dry Run）

執行完整的部署流程邏輯，但**不實際複製或修改任何檔案**。適合在正式部署前驗證流程是否正確。

1. 選擇應用程式、環境、目標及版本。
2. 點擊 **模擬部署** 按鈕。
3. 完成後，下方結果區域顯示「模擬完成」訊息，並建立一筆 DryRun 部署記錄。

> 模擬部署不會修改任何檔案，也不會觸發備份。

### 7.3 正式部署

將所選版本實際部署至目標機器的指定路徑。

1. 選擇應用程式、環境、目標及版本。
2. 點擊 **部署** 按鈕（藍色強調按鈕）。
3. 確認對話框顯示版本、應用程式、環境、目標資訊及備份提示，確認無誤後點擊 **是**。
4. 部署完成後，下方顯示部署 ID 及成功訊息。

**部署流程：**
1. 驗證來源版本與目標設定
2. 自動備份目前部署目錄
3. 將版本壓縮包解壓縮到目標路徑
4. 更新目標的目前版本記錄
5. 寫入稽核記錄

> 若目標路徑不存在，系統會自動建立。部署過程使用檔案鎖防止同時多人部署。

### 7.4 版本回滾

將目標還原至指定的歷史版本，適用於新版本發生問題需要緊急回退的情況。

1. 在版本下拉選單中選擇要回滾至的歷史版本。
2. 點擊 **回滾** 按鈕。
3. 確認對話框顯示將回滾的應用程式、環境、目標及目標版本，確認後點擊 **是**。
4. 完成後下方顯示回滾部署 ID 及成功訊息。

> 回滾本質上是部署一個舊版本的操作，同樣會自動備份目前目錄再執行覆蓋。

## 8. 備份管理

點擊左側導覽列中的 **備份** 進入此頁面。可手動建立備份、設定保護狀態及清理過期備份。

**備份清單欄位：**

| 欄位 | 說明 |
|---|---|
| Backup ID | 備份的唯一識別碼 |
| Release | 備份時目標上已部署的版本號碼 |
| Created | 備份建立時間 |
| Files | 備份的檔案數量 |
| Size | 備份壓縮包的總大小（B / KB / MB / GB） |
| Status | 備份狀態（Completed / Failed） |
| Protected | 是否已受保護（是 / 否）。受保護的備份不會被自動清理 |

### 8.1 建立備份

1. 使用目標選擇器選擇應用程式、環境及目標。
2. 點擊 **建立備份** 按鈕。
3. 系統自動壓縮目標路徑的內容（排除清單中的目錄除外），完成後顯示備份 ID 與檔案數量。

### 8.2 保護／取消保護備份

1. 在備份清單中點擊選取一筆備份（列會變色高亮）。
2. 點擊 **保護備份** 按鈕。
3. 確認對話框後，Protected 欄位切換為「是」或「否」。

> 已保護的備份在執行清理時不會被刪除，適合用於保留特定的里程碑版本備份。

### 8.3 清理過期備份

依據系統保留原則自動刪除符合條件的舊備份。

1. 選擇目標。
2. 點擊 **清理備份** 按鈕。
3. 確認對話框後執行清理，完成後顯示清理成功訊息，清單自動重新整理。

> 已受保護的備份不會被清理。

## 9. 歷史紀錄

點擊左側導覽列中的 **歷史** 進入此頁面。包含**部署歷史**與**稽核記錄**兩個分頁。

### 9.1 部署歷史

顯示指定目標的所有部署作業記錄（包含正式部署、模擬部署及回滾）。

1. 切換至 **部署歷史** 分頁（預設為此分頁）。
2. 使用目標選擇器選擇應用程式、環境及目標。
3. 清單自動載入該目標的所有部署記錄。

**欄位說明：**

| 欄位 | 說明 |
|---|---|
| Deployment ID | 部署的唯一識別碼 |
| Release | 部署的版本號碼 |
| Status | Completed（綠）、Failed（紅）、Cancelled（灰）、RolledBack（綠） |
| Operator | 執行部署的使用者名稱 |
| Started | 部署開始時間 |
| Completed | 部署完成時間 |

### 9.2 稽核記錄

顯示系統中所有操作的完整稽核軌跡，可依應用程式與環境篩選。

1. 切換至 **稽核記錄** 分頁。
2. 使用頁面上方的應用程式、環境下拉選單篩選記錄範圍。
3. 點擊 **重新整理** 更新清單。

**欄位說明：**

| 欄位 | 說明 |
|---|---|
| Timestamp | 事件發生時間（本地時間） |
| Event | 事件類型，如 `DEPLOY_STARTED`、`DEPLOY_COMPLETED`、`BACKUP_CREATED` 等 |
| Target | 對應的應用程式/環境/目標路徑 |
| Operator | 執行操作的使用者名稱 |
| Result | SUCCESS（綠）、FAILED（紅）、STARTED（綠） |
| Details | 詳細資訊，如錯誤訊息或操作說明 |

## 10. 異常復原

點擊左側導覽列中的 **復原** 進入此頁面。用於處理因系統意外中斷而停留在「進行中」狀態的部署作業。

頁面頂部會顯示目前發現的未完成部署數量。

**操作步驟（標記為失敗）：**

1. 進入頁面後，系統自動掃描並列出所有未完成的部署記錄。
2. 在清單中點擊選取需要標記的記錄。
3. 點擊 **標記為失敗** 按鈕。
4. 確認對話框後，系統將該部署狀態改為 Failed，並寫入一筆稽核記錄。

> 標記失敗後，部署鎖會自動釋放，可重新對該目標執行部署操作。此功能通常在系統異常重啟後使用。

## 11. 常見問題

**Q：開啟程式時出現「資料庫初始化失敗」錯誤？**  
A：請確認 `%APPDATA%\deployctl\` 目錄有寫入權限，或以管理員身分執行 deployctl-desktop.exe。

**Q：部署時顯示「目標正被鎖定中」？**  
A：可能有另一個部署正在進行，或上次部署異常中斷。若確定無其他人在操作，請至「復原」頁面將卡住的部署標記為失敗，鎖即可釋放。

**Q：差異比較顯示空白？**  
A：表示所選版本與目標目前版本完全相同，無需部署。

**Q：備份清理後磁碟空間沒有立即釋放？**  
A：備份壓縮檔刪除後，磁碟空間由作業系統回收，有時需要數秒至數分鐘。

**Q：建立版本時出現「來源資料夾不存在」錯誤？**  
A：請確認來源路徑輸入正確，且目前使用者對該路徑有讀取權限。
